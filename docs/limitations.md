# Limitations

Phase 3A.3 adds aggregate compiler-graph and shared component-tree budgets without changing .qb syntax. Reactive bindings remain dependency-based; child props refresh without remounting, and failed structural preparation retains committed identity, focus, selection and local state.

Limits are deliberately generous defaults, not workload guarantees. They cover distinct resolved modules, parsed AST objects and framework-accounted component instances, list records, DOM nodes, effects and synchronous work. They do not measure JavaScript object size, CSS/layout cost, browser internals, host allocations, asynchronous activity or resources retained by trusted getters, proxies, mounts and cleanup callbacks. A host can still exhaust resources before a configured ceiling if individual host values or platform operations are unusually expensive. Raise limits only for reviewed trusted workloads.

Structural preparation is reversible. Cleanup after commit is irreversible: cleanup errors are post-commit errors and committed state stays committed. Recovery failure disables participating components and reports the combined error. Key uniqueness is checked when an iteration is prepared, so invalid data created in an inactive branch fails on activation and rolls back. The null-prototype scopes and own-property definition used for names such as __proto__ are defense in depth; the earlier review did not reproduce a prototype-pollution exploit.

Classes have no inheritance, custom constructors, static members or arbitrary methods. Empty typed lists, filtering/sorting expressions, indexes, nested collection mutation, routing, SSR, plugins, LSP/editor extensions, native targets and a registry remain unsupported. Transactions are synchronous and do not cover timers, promises, network activity or arbitrary trusted-host side effects. Development uses full reload after edits; state-preserving HMR and generated JavaScript source maps are deferred. Packages remain private/unpublished.
