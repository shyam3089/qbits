# Limitations

Phase 2D supports the Phase 2B component, prop, form and conditional syntax plus file-local classes with literal fields, computed values and parameterless actions; typed non-empty list state; keyed iteration; append/remove/move operations; and component init/cleanup blocks. Reactive DOM bindings subscribe to the state, computed values, or instance fields they read. Synchronous event batches settle computed dependencies before updating affected bindings. Child prop signals refresh without remounting; keyed list records retain identity, focus and selection during reorder.

Classes have no inheritance, access modifiers, custom constructors, static members or arbitrary methods. List item types are inferred from a non-empty literal; empty typed lists, filtering, sorting expressions, indexes and nested collection mutation are deferred. Actions and handlers accept only validated assignments, class actions and list operations. Lifecycle blocks are synchronous and accept the same closed statements.

`or`, ordering comparisons, broader operators, additional event members and controls, arbitrary calls, component children/slots, routing, SSR, plugins, LSP/editor extensions, native targets and a registry remain unsupported. Numeric literals are nonnegative safe integers; negative safe integers can come from host props. Literal-only arithmetic overflow is a compile error, and runtime arithmetic/writes reject unsafe results before committing invalid state. List mutation targets must be writable list-state names; computed lists, temporary expressions and loop bindings are read-only. Validation and duplicate-key failures roll back synchronous signal updates before DOM commits. Phase 3A stages structural changes before committing; recoverable DOM failures restore the previous state and owned nodes. Unrecoverable host DOM failures dispose the affected component; cleanup errors are reported after committed rendering and do not roll back that commit. Class computed results cache their input values. See reactivity.md for boundaries. Development uses full reload after source edits; state-preserving HMR and generated JavaScript source maps are deferred. Packages remain private/unpublished. No performance claims are made without benchmarks.
