# Security

Parsing never executes application source, generation serializes literals, and rendering uses DOM element/text/property APIs rather than HTML insertion. Numeric values and arithmetic results are finite safe integers, including literals supplied through direct runtime models. Synchronous structural transactions prepare before commit; a failed reservation or staged mount preserves committed DOM identity, focus, state and subscriptions. Recovery failure is reported and disables participating components rather than continuing with uncertain state.

Compiler module resolution is iterative. Graph-wide defaults are 10,000 distinct modules, import depth 256, 64 MiB cumulative UTF-8 source, and 2,000,000 aggregate AST objects. Shared imports are counted once. Direct compile, compileFile, CLI and Vite use the same limit model; CLI overrides are --max-modules, --max-import-depth, --max-project-bytes and --max-project-complexity. Programmatic callers pass graphLimits. Existing per-file defaults remain 2,097,152 UTF-16 code units, nesting 256, 100,000 expression nodes, expression depth 512 and 100,000 collection items.

Each root component tree shares defaults of 100,000 component instances, 250,000 live list records, 500,000 framework-created DOM nodes, 250,000 reactive effects and 1,000,000 units of mount/update work. The existing limits of 100,000 items per collection, component depth 256 and 100,000 effect executions per flush also apply. Detached staged mounts, prop/state/class-field initialization and initial effects are included. Reservations are released on rollback and disposal. All values are configurable positive safe integers through compiler or mount options; raising them transfers exhaustion risk to the host.

These controls bound framework-accounted synchronous work, not total process memory, browser layout/paint cost, dependency behavior or arbitrary host JavaScript. Component mount/cleanup functions, application code, prop getters/proxies, Vite configuration and npm dependencies are trusted and can execute with normal host permissions or retain resources outside the accounting model. Transactions do not span timers, promises, network activity or other asynchronous side effects. This is defense in depth, not a sandbox or security certification.

HTTP client auth and interceptor capabilities must be explicitly supplied by trusted host JavaScript. Qbits copies them into a frozen null-prototype registry, so names inherited from Object.prototype are not treated as configured functions. Bearer tokens require HTTPS outside loopback, remain client-controlled, and authenticated request interceptors cannot change request origin.

Typed HTTP success and declared error bodies are validated recursively as exact plain-object/list schemas before application code receives them. Form 422 mappings accept only bounded, unique JSON-pointer-style paths, reject malformed escapes, prototype-related segments, unknown fields, and removed snapshot entries, and resolve array indexes against the submission snapshot. Validation transport failures remain separate from user validation failures. Async validator generations, cancellation and component cleanup prevent stale responses from mutating current form state; trusted server and host side effects remain outside transactional rollback. Fetch-backed JSON responses are bounded by schema depth and item count, but not by a response-byte ceiling before parsing; applications must enforce response-size limits at the server or transport boundary.

Nested routes remain one statically compiled router tree. Typed path numbers require canonical safe integers, query values are converted only to their declared primitive defaults, and malformed typed URLs select a bounded fallback rather than entering component state. Multiline navigation resolves a compiler-known route, requires every path argument, encodes path and query values, and still passes the same-origin URL checks. Route matching and client-visible fallbacks are not authentication or authorization boundaries.

WebSocket connections accept only same-origin ws:/wss: targets relative to the page or selected HTTP client base; secure pages require wss:. Credentials and URL fragments are rejected. Browser WebSockets cannot set application-defined Authorization headers, so Qbits does not invoke bearer providers or place bearer tokens in socket URLs. Inbound text is limited to 1 MiB, outbound messages to 64 KiB, and queued outbound data to 1 MiB. Binary input is rejected.

SSE accepts only same-origin HTTP(S) targets relative to the page or selected HTTP client base; non-loopback streams require HTTPS. Credentials and URL fragments are rejected. Qbits does not invoke bearer providers, apply HTTP interceptors, add Authorization headers, or place tokens in stream URLs. Same-origin cookies follow browser policy. SSE text messages are limited to 1 MiB, and failed EventSource instances are closed before bounded framework reconnection.
