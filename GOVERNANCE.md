# Governance

The project founder approves language syntax and semantic changes. Proposals should
include motivation, a minimal example, compatibility impact, and tests. Record
approval in the change discussion before merging. The repository does not yet name
individual maintainers or establish a voting process.

Security-sensitive compiler, runtime, dependency, and CI changes require independent
human review by someone other than the author. These are project policies, not
technical enforcement of GitHub permissions. Maintainers must configure branch
protection and access separately. This implementation changes neither.

Packages remain private; an open-source license decision is pending founder approval.
Publishing, deployment, and registry governance are outside Phase 1.
